Set a Collection up on one page, and change a field after it exists.

A Collection's settings are one page. The Collection name and the Entry name, the Collection slug and the Entry slug, the description, and then every field as editors will see it. One Save, and a More menu beside it that holds Delete Collection. The title and Save stay in place while the page scrolls. Create Collection opens the same page, empty, and a settings button at the head of a Collection's list of Entries opens it.

Add field opens a pane with all 18 field types, in groups, each with its icon: Text, Numbers, Choices, Dates and times, Contact and web, and Links. Choosing one adds the field and opens its settings right away, so there is nothing left to confirm.

A field can be changed after it exists, which was not possible before. Choosing a field opens its settings filled with what is stored: its Label, its Type, its Slug, its Description, its Width, the rules its type takes, a Default Value where the type takes one, and Required, Unique and Disabled. Its More menu moves the field up, moves it down and removes it, with no dragging needed, and the grip is still there for whoever prefers to drag. Every list a type takes is rows with Add and Remove: a select's options, the Collections an Entry field points into, the Components a section may be built from, the blocks and marks a markdown field allows, the file types a reference takes, and the fields a slug is written from.

The fields beside the pane follow every edit at once, so what editors will see is on screen before anything is saved. A field keeps its identity through every change, including a change of its type, which is what keeps the Values every Entry holds: a renamed slug moves its Values, a looser rule applies, and a type change goes through wherever the stored Values fit the new type. A change elek.io Core will not carry out saves nothing at all and says so, and the Collection stays exactly as it was.

One language switch above the page switches every name, every label and every description, with the line "Switches names, labels and descriptions. Slugs and fields are the same in every language." Save waits while a language is still missing one of them and says which language misses how many, such as "German is missing 1 translation". Leaving the page with changes nobody saved asks first.

Every refusal is said in words an editor uses, below the field it is about: a slug two fields share, a slug elek.io keeps for itself, a minimum above a maximum, a Default Value outside a field's own bounds, and a unique field that carries a Default Value. None of them shows the English a validator wrote.

A Component's fields are defined with the same editor and the same language switch.
